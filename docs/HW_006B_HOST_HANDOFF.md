# HW-006B host implementation handoff

Target repository: `EMajesty/neurogenic`. Start from the normative revision
recorded in `protocol/upstream.lock.json`, then re-audit current `main` before
editing. Upstream remains the contract owner.

## Contract work

1. Preserve every 1.3 ID, message, fingerprint and validation rule. Add a
   maximum supported minor only after approving the extension; proposed policy
   is minor 1.4 with mutual-minor selection and exact 1.3 fallback.
2. Approve or replace independent capability bits proposed as 11 (P1-P8 push)
   and 12 (P1-P8 RGB destination). Unknown bits must be ignored.
3. Approve the provisional push IDs `0x0160..0x0167`, identities
   `parameter.1.push..parameter.8.push`, and an explicit optional-inventory
   fingerprint algorithm. Do not change `0x3256434e`.
4. Reuse `parameter.1..8` IDs as LED_RENDER destinations in a separate
   destination namespace. Do not allocate eight redundant destination IDs.
5. Approve the conditional INVENTORY records and conditional one-byte
   INPUT_STATE push suffix, or define another bounded representation. Freeze
   bytes only in the upstream header and tests.

## Host implementation order

- Extend the codec and `ControllerHost` negotiation first. Validate capability
  and inventory together before enabling either optional namespace.
- Extend descriptor/inventory lookup with optional button descriptors. Keep
  them unassigned by default; semantic registry integration must not invent an
  action. Existing parameter rotations remain unchanged.
- Extend snapshot validation/quarantine with eight optional bits only in the
  negotiated mode. Preserve no-synthetic-press behavior, generation rejection,
  gap recovery, reconnect cancellation and lost-release recovery.
- Route optional BUTTON events through the existing bounded input path only
  after negotiation. A 1.3 session must reject/suppress them.
- Project contextual encoder feedback from the host's semantic state into the
  existing LED_RENDER RGB/brightness/mode fields. Host owns functional color,
  normalized musical magnitude, assigned/unavailable/selected decisions and
  the single minimum-visible rule. Firmware owns calibration, gamma,
  interpolation, electrical limiting and scheduling.
- Extend the Reference Controller V2 simulator with baseline, push-only,
  RGB-only, both, bad-inventory, unknown-bit, reconnect and stale-generation
  personalities. Exercise production codec/session paths.
- Force a complete current input reconciliation and complete desired feedback
  refresh after negotiation. Clear old connection queues before replacement.

## Required acceptance

Import the baseline vectors under `protocol/fixtures` and prove upstream still
emits/accepts them. Add normative extension golden vectors generated by the
upstream implementation after the contract is approved. Test all rows in
`PROTOCOL_COMPATIBILITY_MATRIX.md`, bounded frame limits, malformed lengths,
CRC, optional IDs, canonical inventory bytes, snapshot lengths, event gaps,
duplicate/stale input, feedback convergence and host crash/heartbeat behavior.

Update the upstream wire header, protocol/controller documentation, simulator
documentation and visual-feedback ownership documentation in the same change.
Publish the approved upstream commit SHA for HW-006C; proposed fixture numbers
in this repository are not authority.
